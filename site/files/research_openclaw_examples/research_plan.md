# Research plan: stronger OpenClaw examples

## Main question

Which current OpenClaw and ClawHub capabilities, workflow patterns, and safety boundaries should shape a 300-example repository so the new entries are useful, reproducible, and honest?

## Subtopics

1. OpenClaw workflow primitives: identify the supported interaction surfaces, scheduling/session patterns, and operational constraints that examples can document.
2. ClawHub skills and discovery: verify how skills are installed, described, and scoped so example stacks use realistic dependencies and explain trust boundaries.
3. High-value use-case patterns: compare official or first-party examples and recurring automation patterns to choose distinct domains rather than title variants.
4. Safety and reproducibility: identify guidance for permissions, external side effects, prompt-injection resistance, and human review.

## Synthesis

Findings will become the design rules for the generated starter packs, README positioning, validation checks, and the site’s trust language. External sources will be linked in the repository research note and cited in the delivery summary.
